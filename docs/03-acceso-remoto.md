# Fase 3: acceso desde fuera de casa (Tailscale)

> **Versiones usadas:** Debian 13.7, Tailscale 1.104.7, iOS con la app de Tailscale y Moonlight.

## 1. Qué vamos a hacer y por qué

**En sencillo:** una red privada entre tus dispositivos y el servidor, por internet y cifrada. Desde el móvil, estés donde estés, ves Jellyfin y el escritorio remoto como si estuvieras en casa, **sin abrir nada en el router**.

**Técnicamente:** Tailscale en el servidor con la etiqueta `tag:server` y una política que solo permite SSH, Jellyfin y Sunshine desde los dispositivos del dueño. Firewall y Docker abiertos solo para la tailnet. Decisión y alternativas: [ADR 0009](decisiones/0009-tailscale.md).

## 2. Conceptos previos

- **Tailnet:** la red privada de Tailscale. Cada dispositivo tiene una IP `100.x.y.z` (rango `100.64.0.0/10`).
- **Coordinador:** el servicio de Tailscale reparte las claves públicas y la política. El tráfico va cifrado de extremo a extremo con WireGuard.
- **Conexión directa o por repetidor (DERP):** Tailscale intenta conectar los dos extremos directamente. Si una red lo impide, el tráfico pasa por un repetidor de Tailscale, todavía cifrado.
- **Etiqueta (`tag`):** identidad de un dispositivo que no pertenece a una persona. Su clave no caduca.
- **Grants:** las reglas de acceso de la política: origen, destino y puertos.

## 3. Requisitos y estado inicial

- Cuenta gratuita de Tailscale (plan Personal), con un proveedor de identidad con verificación en dos pasos.
- Firewall del [paso 7](01-base-y-endurecimiento/07-firewall.md) y Jellyfin con su regla en `DOCKER-USER` ([stack](../stacks/jellyfin/README.md)).

## 4. Pasos

### 4.1 Política de acceso

En el panel de Tailscale, **Access controls** → **JSON editor**, sustituyendo todo el contenido:
```
{
  "tagOwners": {
    "tag:server": ["autogroup:admin"],
  },
  "grants": [
    {
      "src": ["autogroup:member"],
      "dst": ["tag:server"],
      "ip": [
        "tcp:22",
        "tcp:8096",
        "tcp:47984", "tcp:47989", "tcp:48010",
        "udp:47998-48000",
      ],
    },
  ],
}
```
Sin la regla por defecto, que lo permite todo, los dispositivos personales no se ven entre ellos; solo llegan al servidor.

En la [Fase 4](04-dns.md#47-tailscale-adguard-también-fuera-de-casa) se añaden `"udp:53", "tcp:53"` a la lista `ip`, para el DNS.

### 4.2 Instalar en el servidor

Clave del repositorio: `2596 A99E AAB3 3821 893C 0A79 458C A832 957F 5868`, la misma en `pkgs.tailscale.com`, `keyserver.ubuntu.com` y `keys.openpgp.org`. También firma el `InRelease` de `trixie`.

```bash
sudo curl -fsSL -o /usr/share/keyrings/tailscale-archive-keyring.gpg https://pkgs.tailscale.com/stable/debian/trixie.noarmor.gpg
```
```bash
gpg --show-keys --with-fingerprint /usr/share/keyrings/tailscale-archive-keyring.gpg
```
✅ La huella de arriba.

`/etc/apt/sources.list.d/tailscale.sources`:
```
Types: deb
URIs: https://pkgs.tailscale.com/stable/debian
Suites: trixie
Components: main
Architectures: amd64
Signed-By: /usr/share/keyrings/tailscale-archive-keyring.gpg
```
`/etc/apt/preferences.d/tailscale`: prioridad 1 para todo `pkgs.tailscale.com` y 500 para `tailscale`, igual que con Sunshine ([Fase 2](02-escritorio-remoto.md)). El paquete `tailscale-archive-keyring` entra como dependencia y mantiene el mismo archivo de clave.

`/etc/apt/apt.conf.d/55homelab-unattended-upgrades-tailscale`:
```
Unattended-Upgrade::Origins-Pattern {
        "origin=Tailscale,label=Tailscale,codename=trixie";
};
```
```bash
sudo apt update
```
```bash
sudo apt install tailscale
```

### 4.3 Conectar el servidor

```bash
sudo tailscale up --advertise-tags=tag:server --accept-dns=false
```
Abre el enlace que muestra, en un navegador con la sesión de Tailscale, y pulsa **Connect**.

**Comprueba siempre el DNS justo después:**
```bash
cat /etc/resolv.conf
```
✅ `# Generated by NetworkManager` con los DNS de siempre. Si pone `generated by tailscale` y `100.100.100.100`:
```bash
sudo tailscale set --accept-dns=false
```
Aquí pasó: el agente se quedó sin DNS hasta corregirlo.

```bash
tailscale status
```
✅ El servidor con su IP `100.x` y la etiqueta.

### 4.4 Firewall

UFW, solo en `tailscale0`:
```bash
sudo ufw allow in on tailscale0 to any port 22 proto tcp comment 'SSH tailnet'
```
Igual con `47984`, `47989` y `48010` (TCP), y:
```bash
sudo ufw allow in on tailscale0 to any port 47998:48000 proto udp comment 'Sunshine tailnet'
```
Para intentar conexiones directas, el puerto de WireGuard de Tailscale, solo en el firewall del servidor (en el router no se abre nada):
```bash
sudo ufw allow 41641/udp comment 'Tailscale directo'
```

**Jellyfin.** Los puertos de Docker no pasan por UFW. En `/etc/systemd/system/homelab-jellyfin-lan.service`, una regla `RETURN` para la tailnet antes del `DROP`:
```
ExecStart=/usr/sbin/iptables -I DOCKER-USER -p tcp -m conntrack --ctorigdstport 8096 --ctdir ORIGINAL ! -s <RED_LAN> -j DROP
ExecStart=/usr/sbin/iptables -I DOCKER-USER -p tcp -m conntrack --ctorigdstport 8096 --ctdir ORIGINAL -i tailscale0 -s 100.64.0.0/10 -j RETURN
```
Con sus dos `ExecStop` equivalentes (`-D`). Cada `-I` inserta arriba, así que el `RETURN` queda primero.

En el `compose.yaml`, publicado en todas las IPv4. La IP de Tailscale puede no existir aún cuando arranca Docker, y con una IP inexistente el contenedor no arrancaría:
```yaml
    ports:
      - "0.0.0.0:8096:8096/tcp"
```
`0.0.0.0` y no `8096:8096`: así no se publica por IPv6, donde `DOCKER-USER` de `iptables` no filtra.

```bash
sudo systemctl daemon-reload
```
```bash
sudo systemctl restart homelab-jellyfin-lan.service
```
```bash
sudo docker compose -f /srv/jellyfin/compose.yaml up -d
```
```bash
sudo iptables -S DOCKER-USER
```
✅ Primero `RETURN` con `tailscale0` y después `DROP`.

En Jellyfin, **Panel de control** → **Redes** → **Redes locales**: `<RED_LAN>, 100.64.0.0/10`. Pon las dos: si solo estuviera la de Tailscale, la red de casa dejaría de contar como local. Reinicia Jellyfin.

### 4.5 Dispositivos

App de Tailscale en el iPhone (y en el PC y el iPad cuando se usen), con la misma cuenta.
- **Jellyfin:** `http://<IP_TAILSCALE_SERVIDOR>:8096`. Con datos móviles, la calidad máxima en el cliente a 4-6 Mbps.
- **Moonlight:** **+** → `<IP_TAILSCALE_SERVIDOR>`, y el PIN en el panel de Sunshine desde casa (`https://<IP_SERVIDOR>:47990`, pestaña **PIN**). Con datos, la velocidad de vídeo a unos 5 Mbps.

## 5. Verificación

- [x] El DNS del servidor sigue siendo el de NetworkManager, y Tailscale tiene `CorpDNS: false`.
- [x] `tailscale status`: el servidor con `tag:server`.
- [x] `DOCKER-USER`: `RETURN` de la tailnet y `DROP` del resto; Jellyfin sigue funcionando en casa.
- [x] Desde el iPhone con datos y sin Wi-Fi: Jellyfin y Moonlight funcionan.
- [x] `tailscale netcheck` en el servidor: UDP sí y `MappingVariesByDestIP: false`. Con el iPhone en datos, la conexión va por el repetidor de Madrid (`tailscale ping`: `via DERP(mad)`, 40 ms).
- [ ] SSH por la tailnet: pendiente de Termius o del PC con Tailscale.
- [ ] Tras un reinicio: Tailscale conecta solo y Jellyfin arranca. En la sesión en persona.

## 6. Errores frecuentes

| Síntoma | Causa | Solución |
|---|---|---|
| El agente se queda sin conexión al conectar Tailscale | Tailscale puso su DNS (`100.100.100.100`), y el filtro del agente bloquea `100.64.0.0/10` | `sudo tailscale set --accept-dns=false` |
| Jellyfin: "servidor no disponible" por Tailscale, aunque `tailscale status` muestra tráfico | Jellyfin no considera local la tailnet | Añadir `100.64.0.0/10` a **Redes locales**, junto a `<RED_LAN>`, y reiniciar Jellyfin |
| Va lento fuera de casa | Datos móviles por debajo de lo que pide el vídeo, y conexión por repetidor | Bajar la calidad en el cliente |
| `direct connection not established` | La red móvil no permite conexiones directas | Nada que hacer desde casa; desde otros Wi-Fi suele ir directa |
| `tailscale netcheck` dice `UDP: false` | Se ejecutó como el agente, cuyo filtro bloquea UDP | Ejecutarlo como `<USUARIO_ADMIN>` |

## 7. Cómo revertirlo

```bash
sudo tailscale down
```
```bash
sudo apt purge tailscale
```
Borra los archivos de 4.2 y quita las reglas de UFW con `sudo ufw status numbered` y `sudo ufw delete <número>`. Restaura `homelab-jellyfin-lan.service` y `compose.yaml` desde sus copias `.bak-AAAAMMDD`. En el panel de Tailscale, borra el servidor de **Machines**.

## 8. Seguridad

**Mitiga:**
- Acceso desde fuera sin exponer nada a internet ni tocar el router.
- Mínimo privilegio: solo los dispositivos del dueño, solo hacia el servidor y solo tres servicios. El servidor no llega a los dispositivos.
- Defensa en dos capas: la política de Tailscale y el firewall del servidor.

**Queda:**
- Confianza en Tailscale como coordinador. Tailnet Lock lo cubriría (exige dos nodos firmantes): mejora pendiente.
- La cuenta de Tailscale es una llave de la casa: con verificación en dos pasos.
- Jellyfin va por HTTP: en la tailnet el tráfico ya va cifrado por WireGuard, pero en la LAN no, hasta que llegue Caddy (Fase 4).
- `autogroup:member` da acceso a cualquier usuario que se invite a la tailnet.

## 9. Para la entrevista

**En 30 segundos:** "Para entrar desde fuera no abrí nada en el router: usé Tailscale. El servidor entra con una etiqueta, para que su clave no caduque y no dependa de un usuario, y la política solo deja que mis dispositivos lleguen a tres servicios del servidor, sin que el servidor pueda llegar a ellos. En el servidor abrí esos puertos solo en la interfaz de Tailscale, y para Jellyfin, como Docker se salta UFW, añadí una regla en `DOCKER-USER`. Al conectar, Tailscale cambió el DNS y dejó sin conexión al agente de IA, cuyo filtro bloquea ese rango; desde entonces compruebo `/etc/resolv.conf` después de conectar."

**Preguntas posibles:**
- *¿Por qué una etiqueta en el servidor?* Un servidor no es una persona: con etiqueta, su clave no caduca y sus permisos se definen como destino, no por quién lo dio de alta.
- *¿Por qué no publicar Jellyfin en la IP de Tailscale?* Si Docker arranca antes de que Tailscale tenga IP, el contenedor no arrancaría. Se publica en todas las IPv4 y se filtra por origen e interfaz.
- *¿Directo o por repetidor?* Con datos móviles, por el repetidor de Madrid. El tráfico sigue cifrado de extremo a extremo; solo añade latencia.
